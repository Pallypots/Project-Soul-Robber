## Rules, in order
1. **Library-named sections** (D3D, D3DX, XGRPH, DSOUND, XACTENG, XPP, WMADEC, DOLBY): owner = that library, **high**. Evidence: XDK 1.0.5849 library table in the header plus the XDK's own section names.
2. **BINK\*** sections: RAD Bink, **high** (section names; Bink entry points known from the recomp work).
3. **`.text` from 0x001BC6D0**: XDK XAPI/LIBCMT, **medium**. Evidence (Verified): in 64 KB buckets, 100% of call-target/prologue function starts are 16-byte aligned from 0x10000 up to 0x1AFFFF, then 66% in 0x1B0000, 21% in 0x1C0000, 15% in 0x1D0000 (game objects compiled with padding vs. libraries without); first run of 8 unaligned starts is at 0x001BC9D6; known XAPI routines DuplicateHandle 0x001BC71B, SwitchToThread 0x001BD332, CreateThread 0x001BD49C, CRT `_ftol2` 0x001C7D38, memmove 0x001C84B0 and the XAPI entry 0x001BEF07 all lie after it. The exact cut (0x001BC6D0, last aligned start before the first unaligned 0x001BC6FD) is **Hypothesis** within a few hundred bytes.
4. **`.text` before it**: game, **medium**. Functions that call the kernel thunk table directly stay game but drop to **low** (38 functions, 0x001A52F0..0x001AA1F0), because XDK headers map `EnterCriticalSection` to the kernel's `RtlEnterCriticalSection`; e.g. 0x001A52F0 is `RtlLeaveCriticalSection(g_renderLock)` (Verified by disassembly).
5. Three CRT signature hits inside the game range (strcmp 0x0016A540, _ftol 0x001A3ED0, strcpy 0x001ADA40) are **unknown, low**: either inlined/duplicated CRT or false signature matches.

## Known gaps (Hypothesis)
- LIBCPMT (C++ standard library) and any game-side middleware may sit inside the "game" range; not yet separated.
- BINKDATA (writable) was swept as code; probably data.
- No RTTI/vtable pass of our own yet; the recomp's func_id reports 318 thiscall functions and vtables, so the game is at least partly C++.

## Denominator change (2026-11-11)
`config/not_functions.csv` lists the inventory entries that recovery work found to be interior fragments of larger functions or jump-table data (all not 16-byte aligned). `tools/progress.py` excludes them from the game total. Their bytes are still covered by the enclosing functions' ranges. Further aligned fragments reported by helpers (e.g. switch-case blocks at 0x639A0, 0x63E00) are not excluded until reviewed.

Added 2026-11-11: every `tail_jump_alias` inventory entry with zero unique bytes, not 16-byte aligned and not recorded as a recovered function (124 entries) - jump targets inside other functions. Game total after exclusions: 7,553 functions; byte total unchanged.
